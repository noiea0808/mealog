# 기록 시트 개편 효과 측정

작성일: 2026-08-26
대상: 2026-08-12~19 기록 시트 개편 (`fb5739e` ~ `05bfb26`)

## 1. 왜 이 문서가 있나

개편은 끝났는데 **효과를 잴 방법이 없었다.**

효과를 재라고 만들어 둔 계측 이벤트 21종(`48c582d` 외)이 `usageDaily` 에 **총 0건**
쌓였다. `functions/index.js` 의 `USAGE_DAILY_METRIC_KEYS` 에 그 키들이 빠져 있어
Callable 이 전부 `invalid-argument` 로 거절했다. 조용히 죽는 종류였다 — 관리자 표에는
행이 멀쩡히 보이는데 값만 0 이라 "기능이 안 쓰인다"와 구분되지 않는다.

`afe192e` 에서 고치고 배포했지만, **8/12~26 사이 2주치는 영구히 없다.** 그 기간은
`meals` 문서에 남은 흔적으로만 소급 측정할 수 있다.

이 문서는 그 소급 측정의 규칙과, 앞으로의 측정 설계를 고정한다.
계산은 [`functions/scripts/entry-sheet-effect.js`](../functions/scripts/entry-sheet-effect.js)
에 있고 규칙은 [`test/entry-sheet-effect-model.test.mjs`](../test/entry-sheet-effect-model.test.mjs)
가 지킨다.

```bash
cd functions && node scripts/entry-sheet-effect.js --credentials=<키.json>
```

2026-08-28 추가 — 아래 표의 **교정률**과 **선택 입력 채움률**은 관리자 화면에서도 바로 볼 수
있습니다: 모니터링 → **모먼트 분석**(기간별 입력률 + 「무엇을」 경로 분해).
스크립트와 숫자를 한 번 대조해 볼 것 — [moment-analytics-handoff.md](moment-analytics-handoff.md) §5.

## 2. 무엇을 「효과」로 볼 것인가

개편의 목표는 **입력 부담을 줄이는 것**이었다(시트 2단계화, 맥락 자동 추측, 분류 제안).
그러면 1차 지표는 「얼마나 적었나」가 아니라 「한 건 적는 데 얼마나 드나」다.

기록 건수를 1차 지표로 쓰면 안 된다. 푸시·시즌·이탈에 다 흔들리고, 같은 기간에 푸시
로테이션 개편(`push-pool`, `push-rotation`)이 함께 들어가서 원인을 가릴 수 없다.

| 층 | 지표 | 정의 | 출처 | 지금 가능? |
|---|---|---|---|---|
| **1차** | 건당 입력 시간 | 연속 저장 간격 중앙값 | `recordedAt` | ✅ 대리 지표로 |
| **1차** | 완주율 | `entry_sheet_saved / entry_sheet_opened` | `usageDaily` | ⏳ 클라 배포 후 |
| 2차 | 추천 수용률 | `(confirmed + auto_saved) / shown` | `usageDaily` | ⏳ 배포 후 |
| 2차 | 교정률(오분류) | `categorySource='user'` / (local+ai+user) | `meals` | ✅ |
| 2차 | 맥락 줄 맞아요율 | `context_predict_applied / shown` | `usageDaily` | ⏳ 배포 후 |
| 가드레일 | 하루 기록 수 | 창 길이로 나눈 건수 | `meals` | ✅ |
| 가드레일 | 선택 입력 채움률 | menuDetail·place·photos·rating·satiety | `meals` | ✅ |
| 가드레일 | 소급입력 비율 | 기록일 ≠ 식사일 | `recordedAt` vs `date` | ✅ |

### 건당 입력 시간이 「대리 지표」인 이유

시트를 **언제 열었는지가 기록에 없다.** 남은 건 저장 시각뿐이라, 한 자리에서 이어 적은
것들의 저장–저장 간격으로 대신 본다. 상한 10분(점심 적고 6시간 뒤 저녁 적은 것이 섞이지
않게), 하한 5초(저장 직후 중복 제거).

`entry_sheet_opened` 가 쌓이면 진짜 완주 시간으로 갈아탄다.

## 3. 측정 방법

### 3.1 도입일은 사용자마다 다르다

개편은 한날한시에 퍼지지 않았다. 8/15 에 한 명, 8/20~8/26 에 나머지가 롤링으로 받았다.
그래서 **달력 날짜로 전후를 가르면 안 된다.**

도입일 = `categorySuggested` 필드가 처음 등장한 **기록일**(`recordedAt` 기준, KST).
이 필드는 개편 이후 저장 경로에서만 생긴다(`js/modals/entry-save-record.js`).

식사 날짜가 아니라 기록일인 이유: 도입은 "언제 새 시트로 적기 시작했나"인데, 며칠 전
끼니를 오늘 적으면 식사 날짜는 과거를 가리킨다.

### 3.2 창은 대칭이어야 한다

W = 도입일부터 기준일까지의 일수. **도입 전도 딱 W 일만 본다.**

```
        [ 도입 전 W일 ]  [ 도입 후 W일 ]
   ─────────────────────┬──────────────────
                     도입일              기준일
```

비대칭으로 자르면 가짜 결론이 나온다. 실제로 처음 돌렸을 때 도입 후 4일과 도입 전 14일을
비교해서 **"기록이 610건 → 220건으로 줄었다"** 는 표가 멀쩡히 출력됐다. 창 길이 차이일
뿐이었다.

### 3.3 진행 중인 날은 뺀다

기준일 기본값은 **어제**다. 오늘은 아직 끼니가 남아 있어 하루 평균을 끌어내린다.
W 가 4~6일뿐인 지금은 하루가 20% 를 흔든다.

### 3.4 짝 비교 — 사용자 간 평균을 내지 않는다

같은 사용자의 도입 전/후를 1:1 로 놓고, 그 결과를 **사용자마다 한 표**로 평균한다.

기록 습관의 개인차가 개편 효과보다 훨씬 크기 때문이다. 하루 5건 적는 사람과 1건 적는
사람의 기록을 통째로 합쳐 평균하면 전자의 변화만 보인다.

표본이 모자란 사용자는 뺀다 — 양쪽 창에 각각 5건 이상, W ≥ 3일. 제외 사유는 출력에
같이 찍어서 "몇 명이 왜 빠졌는지"가 보이게 한다.

## 4. 판단 시점

**전원이 2주를 채우는 9/9 경**이다. 그전 숫자는 방향 참고용이다.

- W 가 3~6일이면 사용자마다 창의 요일 구성이 다르다. 주말이 한쪽에만 들어간 사용자와
  양쪽에 들어간 사용자가 섞인다.
- 14명 며칠치는 우연과 구분되지 않는다.

중간 점검이 필요하면 도입일이 이른 코호트(8/20~8/22, 16명)만 **9/2 경**에 본다.

## 5. 통제 — 원인을 가릴 수 없는 것들

- **푸시 로테이션 개편이 같은 기간에 들어갔다.** 기록 건수가 움직이면 시트 때문인지
  푸시 때문인지 못 가른다. 1차 지표를 건수가 아닌 건당 시간·완주율로 잡은 이유다.
- **운영·스테이징이 같은 Firestore 를 쓴다**(`APP_ID` 동일). meals 는 섞여 들어오지만
  `usageDaily` 는 운영 소스만 기록한다 — 두 지표의 모집단이 다르다.
- **제외 UID** 는 `adminSettings/excludedAnalyticsUids` 를 실행 시점에 읽는다. 목록이
  바뀌면 과거 숫자도 같이 바뀐다.

### 읽는 법

**아직 결론이 아니다.** 다만 방향이 기대와 반대라는 건 담아둘 만하다 — 시트를 2단계로

확인하고 넘어가는 동작이 붙어서일 수 있고, 새 UI에 적응하는 중이어서일 수도 있다.

## 7. 남은 구멍

- **완주율의 분모가 이제 막 생겼다.** `entry_sheet_opened/saved/abandoned/discarded`
  는 서버 화이트리스트에 올라갔지만 이벤트를 쏘는 쪽이 클라이언트라, **앱/웹을
  배포해야** 쌓인다([`js/modals/entry-sheet-session.js`](../js/modals/entry-sheet-session.js)).
- **수정 진입은 완주율에서 뺀다.** 이미 있는 기록을 고치는 것이라 "완주"가 성립하지
  않고 분모가 오염된다. 삭제도 이탈이 아니라 따로 표시해 제외한다.
- **소급 구간의 이벤트는 영원히 없다.** 8/12~26 의 추천 수용률·맥락 맞아요율은
  `categorySource` 같은 문서 흔적으로 대신 볼 수밖에 없다.
