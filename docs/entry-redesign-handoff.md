## 3.5. 2026-08-13 두 번째 세션 (커밋 32개)

설계 근거는 [entry-axes-and-tags-direction.md](entry-axes-and-tags-direction.md) §5에 있습니다.
아래는 **무엇이 왜 바뀌었는지**의 요약입니다.

### A. 입력 시트 구조

- **시트가 2단계가 됐습니다** — 어디서·누구와 전용 페이지를 없앴습니다.
  전체 축 섹션은 1페이지 '자세히' 접힘으로 내렸습니다(건너뜀 칩·서브태그·누구와 상세가
  거기 있어 삭제하지 않았습니다). 지금 '자세히' 트리거는 **렌더에서 빠져 있습니다** —
  모양 검토 중 제외했고, 핸들러·스타일은 남아 있어 다시 붙이면 바로 동작합니다.
  ⚠️ 그 사이 **건너뜀에 UI 진입점이 없습니다**(`window.toggleEntryAxisDetail()` 로만 열림).
- **맥락 한 줄이 1페이지 '무엇을' 아래**에 있습니다. 어떻게·어디서·누구와가 세그먼트고,
  탭하면 그 축의 칩이 인라인으로 열립니다(오버레이 금지 — 키보드 중 높이 재측정 지뢰).
  피커는 고른 뒤에도 닫히지 않고, 해당 세그먼트를 다시 눌러야 닫힙니다.
- **추천 사용 스위치는 기본 꺼짐**입니다. 추천값은 세그먼트에 미리 들어가 있고 OFF에서는
  흐리게만 보입니다 — 켜지 않으면 저장되지 않으므로 원칙 2가 그대로 지켜집니다.
  자동 적용된 축은 `record.autoContext` 에 남고 **다음 예측의 표본에서 제외**됩니다.
- 배달/포장 선택 시 뜨던 '어느 식당 음식인가요' 입력란은 **보류**입니다
  (`DELIVERY_VENDOR_FIELD_ENABLED = false` 한 줄로 되살립니다).

### B. 추론 파이프라인

`무엇을` 텍스트 하나에서 세 세그먼트까지 이어집니다. 신뢰도 순:

1. 카카오 장소 픽 → placeType(식당/술집/카페) → **외식**
2. **원문의 조달 키워드** (배민·배달·구내식당·회식) — 장소가 비어도 발화하는 유일한 규칙
3. 장소 표기 '구내식당'
4. 장소=집 + 형태=밥류·국물요리 → **집밥**
5. **요리 종류** → 개인 통계 우선, 없으면 시드(중식·일식·패스트푸드 → 외식)
6. 습관 예측 (슬롯×평일/주말 최빈값, 표본 3+·점유 60%+)

어떻게가 정해지면 **어디서가 이어받습니다**(집밥·배달/포장→우리집, 구내식당→구내식당).
빈칸일 때만 개입하고, 어떻게가 바뀌면 이어받았던 값은 함께 무효화됩니다.
간식도 같은 예측을 탑니다(축은 어디서·누구와 둘). 표본은 같은 종류(끼니/간식)로 좁혀 뽑습니다.

### C. 음식 사전 — 형태 14개 단일 축

구조를 `카테고리 → 키워드` 에서 **`음식 → { form, cuisine }`** 으로 뒤집고 **최장 일치**를 씁니다
('탕수육'이 '수육'보다 먼저 잡혀 부분문자열 오탐이 구조적으로 사라졌습니다).

| 축 | 값 |
|---|---|
| **형태** (사용자 선택 + ✨제안) | 끼니 몸통: 밥류·국물요리·면류·빵류·고기·생선·채소·샐러드·튀김·분식<br>간식·기호품: 커피·차/음료·술/주류·베이커리/떡·과자/스낵·아이스크림·과일/견과 |
| **요리 종류** (자동 저장 `cuisineAuto`) | 한식·중식·일식·양식·분식·패스트푸드·기타 (+집계값 `혼합`) |

- **형태 축이 간식 축을 흡수했습니다.** 끼니·간식 차트가 섞이지 않는 이유는 차트가
  **슬롯으로 먼저 거르기** 때문입니다.
- **요리 종류를 묻는 형태는 6개뿐**입니다(밥류·국물요리·면류·빵류·고기·생선·튀김·분식).
  나머지 8개는 빈 값이고 요리 종류 투표에서도 제외됩니다.
- 미분류율 22% → **0%** (흔한 음식 59개 기준).
- 관리자 **분류사전**에서 음식별 형태·요리 종류를 **드래그앤드롭으로 편집**할 수 있습니다.
  기본 사전은 코드에 남고 편집분만 Firestore `content/foodDictionary` 에 오버라이드로 쌓입니다.

## 5. 이번 작업에서 배운 것 (반복 방지)

- **서비스 워커 캐시**가 "배포했는데 안 보임"의 단골 원인. 캐시 세대를 안 올리면
  구 HTML + 신 JS가 섞입니다.
- **차트 화이트리스트**(`charts.js` `aggregateProportionData`, `analysis-top-icons.js`
  `getAllowedTags`)는 사용자 태그 밖 값을 '미입력'으로 접습니다. 새 태그 값을 도입하면
  두 곳 모두 열어줘야 차트에서 사라지지 않습니다.
- **키보드 열린 동안 시트 높이 재측정이 막혀 있습니다**(`entry-sheet-tabs.js`).
  입력 중에 새 요소를 띄우려면 늘어난 높이를 `syncEntrySheetHeightLock({growthPx})` 로
  따로 통지해야 합니다. (예전엔 빈 자리를 미리 예약했는데 늘 빈 띠가 보였습니다.)
- **`scrollIntoView` 로 섹션을 열지 마세요.** 화면이 확 튀고 누른 버튼이 시야 밖으로 밀려
  "UI가 통째로 바뀐" 느낌을 줍니다. 시트는 높이 잠금 재측정으로 자라게 두고 스크롤은
  사용자에게 맡기는 편이 낫습니다.
- **추측은 되돌릴 수 있어야 합니다.** '아니에요'로 추측을 지우면 버튼째 사라져 되돌릴 수
  없던 적이 있습니다. 상태 토글은 어느 쪽에서도 사라지지 않아야 합니다.
- **부분문자열 사전은 최장 일치로.** '탕수육'이 '수육'에 걸려 오분류됐습니다.
  항목당 한 표만 세면 한 토큰이 여러 카테고리에 표를 뿌리는 문제도 함께 사라집니다.
- **축을 바꿀 거면 배포 전에.** 실사용 데이터가 0건일 때가 가장 쌉니다.
  미루면 vN 데이터를 쌓은 뒤 vN+1로 옮기는 마이그레이션 빚이 생깁니다.
